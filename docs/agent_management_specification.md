# 複数エージェント管理および対戦検証 仕様書

本仕様書は、ポケモンカードゲーム AI エージェント開発プロジェクトにおいて、チームメンバーがそれぞれ独立したフォルダ（エージェントフォルダ）で並行して開発を行い、それらを競合なく安全に対戦・検証・提出するための設計を定義したものです。

---

## 1. ディレクトリ構成と管理方針

チーム開発を円滑に行い、開発メンバーの利便性（フォルダ単体での完結、IDEでの自動補完、手動提出の容易さ）を最優先するため、以下のように各エージェントフォルダに `cg/` ディレクトリの実体を直接配置して管理します。

```
<project_root>/
├── sample_submission/         # デフォルト・ベースラインエージェント
│   ├── main.py
│   ├── deck.csv
│   └── cg/                    # 共通シミュレータラッパー (C++ライブラリ含む)
├── agents/                    # 開発用エージェントディレクトリ (Git管理)
│   ├── rules_baseline/        # ルールベースエージェント
│   │   ├── main.py
│   │   ├── deck.csv
│   │   └── cg/                # 個別のシミュレータラッパー (実体)
│   ├── mcts_agent/            # モンテカルロ木探索エージェント
│   │   ├── main.py
│   │   ├── deck.csv
│   │   └── cg/                # 個別のシミュレータラッパー (実体)
│   └── deep_q_agent/          # 強化学習エージェント (例)
│       ├── main.py
│       ├── deck.csv
│       └── cg/                # 個別のシミュレータラッパー (実体)
├── tests/
│   ├── dry_run.py             # 動作確認スクリプト
│   ├── benchmark.py           # 対戦ベンチマークスクリプト
│   ├── visualize_match.py     # 対戦可視化スクリプト
│   └── update_cg.py           # cg フォルダ同期スクリプト (新規)
```

### 1.1 開発時の原則
1. **コードの独立性**: 各開発者は `agents/` 配下に自身のサブフォルダを作成してコードを書き、`sample_submission` ディレクトリは原則として変更しません（Kaggle本番の標準サンプルとして元の状態を維持します）。
2. **`cg` パッケージの配置**: 各エージェントフォルダ内に `cg` フォルダを実際に配置します。これにより、IDE上での型補完やインポートエラー防止がそのまま働き、手動で直接そのフォルダを圧縮して Kaggle に提出することも容易になります。
3. **`cg` パッケージの同期化**: 共通 of `sample_submission/cg` 内のモジュールやシミュレータがアップデートされた場合は、同期スクリプト（`tests/update_cg.py`）を実行して、開発中の全エージェントフォルダの `cg/` 内のファイルを一括更新します。

## 2. エージェントの自動検出 (Auto Discovery)

テストやベンチマークを柔軟に行うため、プロジェクト内のエージェントフォルダを動的に自動検出します。

### 2.1 検出条件
以下の条件をすべて満たすディレクトリを「有効なエージェントフォルダ」として自動検出します。
- ディレクトリのパスが `sample_submission` である、または `agents/` 直下のサブディレクトリである。
- そのディレクトリの直下に `main.py`、`deck.csv`、および `cg/` が存在する。

### 2.2 検出 API の実装
`tests/utils.py`（または `tests/benchmark.py` 内部）に検出用ユーティリティを実装します。
```python
def discover_agents(project_root: str) -> dict[str, str]:
    """リポジトリ内の有効なエージェントフォルダを検出する。
    
    Returns:
        dict[str, str]: エージェント名 (ディレクトリ名) をキー、
                       エージェントディレクトリの絶対パスを値とする辞書。
    """
```

## 3. エージェント実行ラッパー (CWD & Path Wrapping)

各エージェントが異なる `deck.csv` を安全にロードし、かつ各自の `cg` パッケージを正確にインポートできるようにするため、エージェント関数の実行時にコンテキストを切り替えるラッパーを導入します。

### 3.1 課題と解決策
- **課題**: エージェント内の `read_deck_csv` は `open("deck.csv")`（CWDからの相対パス）でデッキを読み込みます。複数のエージェント同士を対戦させる際、同一のCWDで実行すると、両者が同じ `deck.csv` を読み込んでしまいます。
- **解決策**: エージェントをロードした際、エージェント関数をラップし、**「呼び出し時に CWD をそのエージェントのディレクトリに一時変更し、終了後に復元する」** という処理を噛ませます。

### 3.2 ラッパー実装イメージ
`tests/benchmark.py` の `load_agent` 関数で以下のようなラッパーを作成して返します。

```python
def make_agent_wrapper(original_agent: Callable, agent_dir: str) -> Callable:
    """エージェント実行時に CWD と sys.path をそのディレクトリに切り替えるラッパー。"""
    def wrapper(obs_dict: dict) -> list[int]:
        original_cwd = os.getcwd()
        # カレントディレクトリをエージェントのディレクトリに変更
        os.chdir(agent_dir)
        try:
            # sys.path にエージェントディレクトリを追加
            import sys
            
            # sys.path の一時的な切り替え
            with temporary_sys_path([agent_dir]):
                return original_agent(obs_dict)
        finally:
            os.chdir(original_cwd)
    return wrapper
```

これにより、個別の `deck.csv` や `cg` モジュールを完全に独立して競合なく動かすことが可能になります。

## 4. テストスクリプトの拡張

### 4.1 動作検証 (`tests/dry_run.py`) の汎用化
- **引数の追加**: `--agent-dir` で任意のエージェントディレクトリを指定可能にします（デフォルトは `sample_submission`）。
- **一括テストモード**: 引数が指定されない場合、自動検出されたすべてのエージェントに対して順次 dry run を実行し、CI/CD においてすべてのエージェントが構文・論理エラーなしで1ゲーム完走できるかを一括検証します。

### 4.2 ベンチマーク (`tests/benchmark.py`) の拡張
- **引数の追加**:
  - `--agent-a`, `--agent-b`: 任意のエージェントフォルダのパス（例: `agents/rules_baseline`）。
  - `--round-robin`: 自動検出されたすべてのエージェント間で総当たり戦を実行するモード。
  - `--baseline <path>`: 指定されたベースラインエージェントと、検出されたすべてのエージェントを対戦させるモード。
- **デッキ読み込みの最適化**: 対戦開始時に、各エージェントの `deck.csv` をパースして `kaggle-environments` の `configuration={"decks": [deck_a, deck_b]}` に渡すように変更します。これにより、シミュレータ初期化段階から各自のデッキが正しく設定されます。

## 5. CI/CD ワークフローの更新

### 5.1 構文・動作検証 (`ci.yml`)
- `dry_run.py` を引数なしで実行し、リポジトリ内のすべてのエージェント（`sample_submission` および `agents/*`）の動作確認を自動で行います。

### 5.2 自動/手動ベンチマーク (`benchmark.yml`)
- **PR時**:
  - `git diff` により変更のあったエージェントフォルダ（例: `agents/mcts_agent`）を自動検出し、`main` ブランチの同一エージェント、あるいは `sample_submission`（標準サンプル）と自動対戦させます。
- **手動実行 (workflow_dispatch)**:
  - Github Actions 上から対戦させたいエージェントAとエージェントBを一覧（または自由入力）から選択し、対戦回数を指定して実行できるようにします。

## 6. cg フォルダ同期スクリプト (`tests/update_cg.py`)

共通の `sample_submission/cg/` に変更（バグ修正やシミュレータライブラリの更新など）があった場合、開発中のすべてのエージェントの `cg/` ディレクトリを同期するユーティリティです。

### 6.1 同期処理ロジック
`python tests/update_cg.py` を実行すると以下の処理を行います。
1. `agents/` 配下の有効なエージェントフォルダを検出。
2. `sample_submission/cg/` 内のすべてのファイル（`libcg.so`, `api.py` 等）を、検出された各エージェントの `cg/` ディレクトリへ上書きコピーします（未存在の場合は作成）。
3. 同期完了のレポートを出力します。
