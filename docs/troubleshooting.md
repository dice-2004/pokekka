本ドキュメントでは、本プロジェクトの開発環境やスクリプト実行中に発生したトラブル、エラーとその解決方法についてまとめています。

## 1. ファイル編集時の文字化け・エンコーディングエラー

### 現象
AI アシスタントが `LOG.md` などのテキストファイルを編集・上書きした際、ファイル全体が文字化け（デコードエラーによる意味不明な記号の羅列）を起こしてしまう。

### 原因
編集対象のファイル内に、前回の書き込みや編集ミスにより**不正なマルチバイトバイト列**（UTF-8 として不正なバイトシーケンス。例: 「優先度」の「優」の次のバイトが欠落していた等）が含まれている場合、ファイル編集ツールがファイルのエンコーディングを UTF-8 ではなく誤ったエンコーディング（Shift-JIS など）と自動判定してしまいます。その誤判定されたエンコーディングで上書き保存されるため、ファイル全体が破損して文字化けします。

### 解決方法
1. **ファイルの復旧**:
   Git 管理下のファイルであれば、以下のコマンドを実行して一度変更を破棄し、正常な状態に戻します。
   ```bash
   git checkout -- <対象ファイルパス>
   ```
2. **不正バイトのクリーンアップ**:
   Python の一行スクリプトなどを使用し、ファイルを UTF-8 且つエラー無視（`errors="ignore"` または `errors="replace"`）で安全に読み込み、問題のある不正なバイト列を正常な UTF-8 文字列にクリーンアップして上書き保存します。
   
   *コマンド例（LOG.md の場合）*:
   ```bash
   python3 -c '
   with open("LOG.md", "r", encoding="utf-8", errors="ignore") as f:
       lines = f.readlines()
   # 問題のある行を安全なUTF-8に書き換え
   lines[7] = "- 開発行動指針(`.agents/AGENTS.md`)の追加・改訂...（中略）...\n"
   with open("LOG.md", "w", encoding="utf-8") as f:
       f.writelines(lines)
   '
   ```
3. **以降の編集**:
   不正バイトが除去された後は、通常のファイル編集ツール（`replace_file_content` など）で編集を行っても文字化けは再発しません。
