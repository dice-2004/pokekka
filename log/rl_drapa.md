# rl_drapa (ドラパルトex + カースドボム RL エージェント) 作業ログ

## 2026-07-19: カリキュラム学習、ルールベース事前学習 (BC) & 逆KL正則化の統合 (ローカル/GCPハイブリッド対応)

### 概要
開発中のドラパルトボム強化学習（RL）において、局所解（自爆回避によるスタック）の防止、正しい対戦ループの構築、およびマルチエージェント対戦によるカリキュラム学習をサポートするため、`train_loop.py` と `training.py` を全面的に拡張・統合した。
（前回の検討段階で一時的に作成した Google Colab 関連ファイル3件は削除し、ローカルGPU / GCP の共通トレーニングスクリプトとして1本化）

### 変更されたファイル

| ファイル | 役割・変更内容 |
|:---|:---|
| `train_loop.py` | 1. 意思決定プレイヤーの分離（先攻・後攻ランダム決定、自分側のターンのみ学習バッファに蓄積）。<br>2. カリキュラム学習の統合（エピソード進行度に応じて対戦相手プール StarEx, DragonBomb, IonoBellibolt, Random から重み付きサンプリング）。<br>3. 計画B-2対応（ルールベースエージェントから簡易ILデータを自己生成し、Behavioral Cloning事前学習を実行、さらに逆KL正則化をPPOに適用しアニーリング減衰）。 |
| `training.py` | 1. `PPOTrainer` に逆KL正則化ターゲットモデル (`il_model`) と正則化係数 `lambda_kl` を追加。<br>2. Behavioral Cloning 事前学習用の `pretrain_step` ヘルパーを新設。<br>3. 価値損失の計算時にブロードキャスト警告を回避するためテンソルを squeeze 処理。 |

### 新機能とアーキテクチャ詳細

1. **対戦相手の分離とバグ修正**
   - 従来は敵ターンの選択肢決定時も自分のモデルを走らせ、かつその状態や行動を自分のバッファに混入させていた問題を解決。
   - 自分のターンのみモデルで決定して `RolloutBuffer` に追加し、相手ターンは対戦相手エージェント（自己対戦の場合は同じモデル、カリキュラム学習の場合はプールから動的ロードしたエージェント）の意思決定関数を呼び出すように分離した。
2. **カリキュラム学習の具体実装**
   - 仕様書第5.3節に基づき、進行エピソード数や勝率に応じて対戦相手とフェーズ（フェーズ1/2/3）を制御。
   - アニーリング計算を行い、フェーズ2の期間（100,000 〜 300,000 エピソード）にかけて、ポテンシャル報酬係数 $\beta$ (0.05→0) と逆KL正則化係数 $\lambda_{\text{KL}}$ (0.01→0) を線形減衰させ、フェーズ3では純粋な自己対戦強化学習に移行。
3. **ルールベースからの簡易IL自己生成と事前学習 (計画B-2)**
   - 局所解へのスタックを防ぐため、`agents/DragonBomb/main.py` (ルールベース) の自己対戦から 200 ゲーム分の状態・行動ペア（簡易ILデータ）を収集し、Behavioral Cloning (BC) でモデルの初期重みを事前学習。
   - 事前学習済みのモデルを `il_model.pt` として保存し、強化学習時の逆KLダイバージェンスの正則化ターゲットとしてロード。

### 検証結果
- **事前学習あり極小テスト**: 正常動作を確認（1試合の自己生成データで1エポック事前学習 → 事前モデルを保存・ロード → PPO強化学習へシームレスに移行し、KL正則化を適用して1ゲーム完走） ✅
- **事前学習スキップ3ゲームテスト**: 正常動作を確認（勝率算出、CSVログ出力、警告なしのクリーンな完了） ✅
- **Flake8 / リンター**: 警告・エラー 0 件 ✅

## 2026-07-19: Google Colab 学習環境の整備 (Colab非推奨化のため廃止・削除)

### 概要
Google Colab (GPU: T4) 上で RL エージェントの学習を実行できるようにするため、
Colab 最適化版トレーニングスクリプト、パッケージングスクリプト、Colab ノートブックの 3 ファイルを新規作成した。

### 作成ファイル一覧

| ファイル | 役割 |
|:---|:---|
| `train_colab.py` | Colab 最適化版トレーニングスクリプト (Google Drive連携、tqdm、グレースフルシャットダウン、自動レジューム) |
| `pack_colab.sh` | Colab 用パッケージ (tar.gz) 作成スクリプト |
| `colab_training.ipynb` | Colab ノートブック (セットアップ→動作検証→学習→可視化→ダウンロードの全フロー) |

### `train_colab.py` の機能

1. **Google Drive 連携**: チェックポイント・ログを `/content/drive/MyDrive/rl_drapa/` に保存
2. **自動レジューム** (`--auto-resume`): 最新チェックポイント (latest.pt) から自動再開
3. **最良モデル自動保存**: 移動平均勝率が過去最高を更新するたびに `best_model.pt` を保存
4. **メトリクスCSVログ**: `episodes.csv` (エピソード結果) と `updates.csv` (PPO損失) を記録
5. **tqdm 進捗表示**: 勝率・報酬・ステップ数をリアルタイム表示
6. **グレースフルシャットダウン**: SIGINT/SIGTERM/KeyboardInterrupt でチェックポイント保存後に安全終了
7. **メモリ使用量表示**: 定期チェックポイント時に GPU/CPU メモリを表示
8. **`--no-drive` モード**: ローカルテスト用の Drive 不使用モード

## 2026-07-02: 初期実装 — RL エージェントコードベースの作成

### 概要
仕様書 `rl_agent_specification.md` に完全準拠した RL エージェントのコードベースを
`agents_draft/rl_drapa/` に新規作成した。

### 作成ファイル一覧

| ファイル | 行数 | 役割 |
|:---|:---|:---|
| `__init__.py` | 1 | パッケージ初期化 |
| `config.py` | 120 | ハイパーパラメータ・定数の一元管理 (frozen dataclass) |
| `state_encoder.py` | 356 | Observation → 構造化テンソル辞書 (17キー) |
| `action_encoder.py` | 330 | Option リスト → 72次元アクション特徴量 (512パディング) |
| `network.py` | 480 | Actor-Critic NN (DeepSets + Pointer Network, 352,481 params) |
| `reward.py` | 190 | PBRS 報酬関数 (カースドボム自爆検出付き) |
| `training.py` | 340 | PPO-Clip + GAE + Huber Loss トレーニングパイプライン |
| `main.py` | 195 | 推論エントリーポイント (Kaggle提出互換) |

### アーキテクチャの要点
- **状態表現**: 978次元 (構造化テンソル辞書形式)
  - フィールドスロット: d=64次元 (CardEmbed 32 + 非Embed 32)
  - グローバル: 210次元 (Embedding Pool 192 + スカラ 18)
- **ネットワーク**: DeepSets方式 → マスク付き Max/Mean/Sum Pool → 統合MLP(1152→128) → Pointer Network
- **共有 CardEmbedder**: 2101×32次元 (全モジュールで単一インスタンス)
- **パラメータ数**: 352,481 (約350KB)
- **報酬**: PBRS (Ng et al. 1999) + サイド差変化 + カースドボム自爆 gamma_bomb=0.2

### 検証結果
1. **モジュールインポートテスト**: 全7モジュール OK
2. **Forward Pass テスト**: ゼロ入力での順伝播 OK (logits/value 正常出力)
3. **統合テスト**: 実ゲームシミュレータ (libcg.so) との21ステップ対戦 OK
4. **エージェントラッパーテスト**: CWD切替付きラッパーでの動作 OK

### 修正点
- 相対インポート (`from .config import ...`) を try/except フォールバック付きに修正
  → Kaggle 提出環境 (CWDベース) とパッケージインポートの両方で動作
- アクションテンソルの MAX_OPTIONS=512 パディングを追加
  → action_mask とアクション特徴量テンソルのサイズ統一
